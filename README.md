# Morning Signal

A single-owner morning news briefing that runs locally or as a private Vercel app. It reads publisher RSS feeds, stores story metadata and brief feed excerpts, and links every story to its publisher. It does not use generated news or an AI service.

## Run locally

Requires Python 3.10 or newer. The app uses only Python's standard library; no package install is needed.

1. Open a terminal in this folder.
2. Run `python server.py` (Windows may use `py server.py`).
3. Open [http://127.0.0.1:8765](http://127.0.0.1:8765).
4. Choose **Refresh feeds**. Feed collection is manual so you can see when it happens and which publishers fail.
5. Stop the server with Ctrl+C. Your preferences, stories, reading list, notes, and new reading history remain in `morning_signal.sqlite3`.

To keep the existing personal database untouched while developing, run against a separate file:

```powershell
$env:MORNING_SIGNAL_SQLITE_PATH = "morning_signal-dev.sqlite3"
python server.py
```

The SQLite app works with Python's standard library. `requirements.txt` is needed only for the MySQL deployment/development path. If using a separate MySQL development database locally, install those requirements, set `DATABASE_URL` and `MORNING_SIGNAL_ALLOW_REMOTE_DATABASE=1` in that terminal, and use a development database rather than production. The app refuses a remote database locally unless that explicit opt-in is set. Do not set `DATABASE_URL` when running the SQLite local app.

## Private Vercel deployment (not yet provisioned)

The Vercel path uses `api/index.py` as a request handler, routes every URL through it, and serves the app shell and assets only after authentication. It uses MySQL when `DATABASE_URL` is set. The local `python server.py` path remains SQLite by default. Database schema setup runs once per warm function instance; a MySQL named lock serializes cold-start initialization. No migration runs on each API request.

### Required environment variables

Create values in the Vercel project settings for **Production** and any preview environment you intend to use. Do not commit values or put them in `vercel.json`.

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | MySQL connection URL with TLS verified by both certificate and hostname (for example, the provider's `VERIFY_IDENTITY` mode; `sslmode=require` alone is insufficient). The handler accepts a verified-TLS MySQL connection URL. |
| `APP_ORIGIN` | Exact HTTPS origin for the deployed app, such as `https://briefing.example.com`; no path. Set it separately for preview domains if those should be usable. |
| `MORNING_SIGNAL_USERNAME` | Owner sign-in name, up to 128 characters. |
| `MORNING_SIGNAL_PASSWORD` | Owner password, 16–1024 characters; use a long, unique secret. |
| `MORNING_SIGNAL_SESSION_SECRET` | Random session-signing secret of at least 32 characters. Generate it with a password manager or secure random generator. |

`.env.example` lists variable names with blank placeholder values. Vercel's encrypted environment settings are the production source of secrets. The app uses a 12-hour signed session cookie with `Secure`, `HttpOnly`, `SameSite=Strict`, and the `__Host-` prefix. Every private page and API request checks the configured origin; state-changing requests require a session-bound CSRF token. Sign out clears the browser cookie. Responses include the app's CSP and no-store security headers. Passwords, cookies, notes, reading activity, and the database URL are not written to application logs by this code. The app does not use Vercel deployment protection as its access control.

### MySQL provider and Vercel setup

For a no-cost development option, TiDB Cloud Starter offers a MySQL-compatible mode with a monthly free quota (currently 5 GiB row storage and 50 million request units for eligible Starter instances). Usage beyond the free quota is blocked unless you configure paid usage; quota and plan terms can change. It speaks the MySQL protocol but is TiDB rather than Oracle MySQL. See [TiDB's current Starter quotas](https://docs.pingcap.com/tidbcloud/serverless-limitations/) and [TLS connection guidance](https://docs.pingcap.com/tidbcloud/secure-connections-to-serverless-clusters/). Other MySQL services can work if they support verified TLS and compatible SQL, but have not been tested here.

1. Create a managed MySQL-compatible project and a **separate development database** for testing. The app requires a TLS-verified URL. For TiDB Cloud Starter, its console gives a host, port `4000`, username, and database; encode reserved characters in username/password and format the URL as `mysql+pymysql://USER:PASSWORD@HOST:4000/DATABASE?ssl_verify_cert=true&ssl_verify_identity=true`. `PyMySQL` verifies the server certificate and hostname. Store the URL only as `DATABASE_URL` in Vercel or the current development shell. This repository has not created or connected to a database provider account.
2. In Vercel, import this repository, keep the repository root as the project root, and add the five environment variables above. `vercel.json` routes all paths through `api/index.py` and sets a 60-second maximum function duration.
3. Deploy a preview with a disposable MySQL development database first. Confirm sign-in, read/write controls, and manual feed refresh. Set `APP_ORIGIN` to the exact preview origin for that environment.
4. Only after verification, configure production variables and deploy. Use the Vercel-provided HTTPS domain or a custom HTTPS domain.

The app requires a working database before its private briefing APIs respond. Feed refresh is user-triggered, not scheduled. In Vercel it uses a 48-second internal budget and short per-feed timeouts; a slow or failing source is shown as failed and other sources continue. The app may show partial results when the function approaches its runtime limit. Vercel documents the Python runtime as Beta and Hobby function duration limits; verify current platform limits before relying on refresh timing: [Python runtime](https://vercel.com/docs/functions/runtimes/python), [Function limits](https://vercel.com/docs/functions/limitations), [project configuration](https://vercel.com/docs/project-configuration/vercel-json). MySQL provider and Vercel quotas, sleep behavior, and connection limits vary by plan and can change. This repository has not been deployed or tested against a live MySQL database, so actual platform routing, runtime packaging, HTTPS cookie behavior, and provider quotas remain to be verified by the account owner.

### Existing SQLite data: backup, import, and rollback

The deployed app does not read or upload `morning_signal.sqlite3` automatically. The importer is a separate operator command. It opens SQLite read-only, prints counts only, validates that the target is a verified-TLS MySQL URL whose exact host and database name match explicit flags, requires `--confirm` for writes, refuses a target with existing user data or customized settings, wraps the copy in one MySQL transaction, and records a fingerprint so repeating the same import is a no-op. A different source snapshot cannot be imported into that already-imported target. It copies story metadata/excerpts, publisher associations and statuses, settings, read/save/hidden flags, notes, feedback, and reading history. It does not copy feed configuration secrets (feed URLs are source code configuration) or the SQLite file itself.

Make a separate local backup before import and verify that both original and backup exist. Example PowerShell commands (substitute your own paths and target identifiers; never put credentials in this README):

```powershell
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
Copy-Item .\morning_signal.sqlite3 ".\morning_signal.sqlite3.pre-mysql-$stamp.bak"
Get-FileHash .\morning_signal.sqlite3, ".\morning_signal.sqlite3.pre-mysql-$stamp.bak"
# Set DATABASE_URL in the current shell to the intended MySQL target, without saving it in a file.
python .\import_sqlite_to_mysql.py --source .\morning_signal.sqlite3
python .\import_sqlite_to_mysql.py --source .\morning_signal.sqlite3 --confirm --expected-host "db.example.test" --expected-database "morning_signal"
```

The first import command is a read-only preflight. The second writes to MySQL; it has **not** been run for this project. Before using it, confirm the exact target hostname and database in the database provider console. Keep the backup outside the Vercel project if possible. Git and Vercel ignore rules exclude SQLite files, database dumps, environment files, and backups.

For rollback, stop using the deployed app and preserve the original SQLite file and its backup; this workflow never changes either. To return to local use, unset `DATABASE_URL` and run with `MORNING_SIGNAL_SQLITE_PATH` pointed at the original or a verified copy. For a bad MySQL provider import, preserve the target for inspection, then provision a fresh empty MySQL database and repeat the import after correcting the cause; the importer intentionally will not overwrite or clear an existing target. Use MySQL provider backup or export tools to make a separate database backup before any later migration or destructive operation. Never upload the SQLite file or backup to Git/Vercel.

Local deployment checks use only fixtures and temporary databases. They do not prove MySQL SQL behavior against a live MySQL server or guarantee that this app fits a particular account's Hobby quotas. There is no automatic retry queue or background refresh; a user can retry a failed feed from the page. The single-owner login has no account recovery flow or distributed brute-force rate limiter; use a strong unique password and keep the deployment URL private.

Before starting a newer version against an existing `morning_signal.sqlite3`, make a separate copy of that file. Startup migrations add missing columns and defaults in place; the regression suite checks that legacy stories, read/saved state, notes, preferences, and reading history survive the schema upgrade.

The server listens only on `127.0.0.1` and refuses to start a second copy on the same port, which avoids old code and new code competing to answer browser requests. If startup says port 8765 is already in use, close the existing Morning Signal server window and retry. No account, cloud service, API key, or external package is required. The interface uses system fonts and makes no browser-side third-party requests. Reading activity, saved stories, notes, and preferences stay in the local SQLite database. The app sends no analytics or reading activity to external services; refreshing contacts configured feed publishers, and opening a publisher link connects your browser to that publisher.

On Windows, check that `py --version` reports Python 3.10 or newer. If `python` or `py` returns “Access is denied” for a `WindowsApps` path, install Python 3.10+ with the Python launcher from python.org, then reopen the terminal and run `py server.py`. This is a Windows command-alias issue; the app itself uses only the Python standard library.

## Sources and editorial configuration

Edit `sources.json` to add, remove, disable, or change feeds. Entries record a stable `id`, publisher group, display name, region, topic, official feed URL, `enabled` flag, verification state, and a short known-terms note. Feeds sharing a `publisher_group` count as one publisher for corroboration and coverage. Only sources marked both `verified` and enabled are fetched. Each feed is independently optional in **Preferences → Sources**. Existing source preferences are preserved when sources are added; new sources appear unchecked for an existing installation until selected. Fresh installs default to configured enabled sources.

The current starter list has these publisher groups and editorial sections:

| Publisher | Feed(s) | Verification and known restrictions |
| --- | --- | --- |
| Times of India | Top Stories | Verified from [TOI's RSS listing](https://timesofindia.indiatimes.com/timesofindia.indiatimes.com/rss.cms). Personal use only; no redistribution or commercial use; direct links required. |
| The Guardian | World, Technology, Business, Science | Verified from [Guardian RSS guidance](https://www.theguardian.com/help/feeds). Personal, non-commercial use under its terms. Four feeds still count as one publisher. |
| CNA | Asia | Verified from [CNA's RSS directory](https://www.channelnewsasia.com/rss). Personal, non-commercial use; terms prohibit modifying or redistributing the feed and require a direct article link. |
| Le Monde | Europe, Africa, Americas | Verified from [Le Monde's RSS directory](https://www.lemonde.fr/en/about-us/article/2026/03/27/le-monde-rss-feeds_6751860_115.html). Strictly personal, non-professional, non-collective use; other use requires authorization and a fee. RSS items provide titles, summaries, and article URLs; articles may require a subscription. |
| Africanews | Latest | **Disabled, unverified.** Its [official RSS directory](https://www.africanews.com/page/widgets/) links to the configured URL, but the endpoint returned an XHTML content type in this review and the terms for retaining local excerpts were not clear. It is not fetched or offered as an enableable preference until reviewed. |
| NASA | News Releases | **Disabled, unverified.** NASA's [RSS directory](https://www.nasa.gov/rss-feeds/) does not confirm this specific endpoint and reuse terms. |

These were selected from publisher-maintained RSS directories or guidance rather than third-party feed generators. Direct feed URLs were checked against those publisher pages; that confirms publication/documentation, not uninterrupted availability or successful parsing on every laptop. The only new feeds that could be verified with explicit RSS terms were CNA and Le Monde. Do not use this personal reader to redistribute feed content; publisher terms can change. No unofficial generator, article-page scraping, or access-control workaround is used.

Feed URLs live in `sources.json`; the page’s **View source status** panel shows the last check and any short error without exposing configured feed URLs to the browser. A failed or malformed feed is recorded with its latest check time; other sources continue. The briefing's **Coverage in this briefing** indicator counts only selected stories whose source feed succeeded today and whose source association was seen in that successful refresh. Failed feeds and older stored source associations are not counted as today's contributions. Regions come from headline/excerpt place detection, with an explicitly configured region-section fallback for Le Monde regional feeds and CNA Asia when no place is detected. Publishers are deduplicated by `publisher_group`. This reports what contributed; it never claims complete or globally balanced coverage. Source availability can change. If a feed stops working, disable it or mark it `unverified` until you have checked the publisher's current feed page and reuse terms. Never point this app at paywall bypasses, login-only pages, or scraping services.

Preferences are saved locally in SQLite: preferred regions/topics, enabled sources, exclusions, briefing length, reading difficulty, daily reading goal, and a configurable freshness window (24 hours, 48 hours by default, 72 hours, or 7 days). Enabled source preferences decide which publishers can contribute stories. Dated stories receive a recency score that falls across the selected window; stale stories are excluded from the main briefing and deep-read slot. Stories without a reliable timezone-aware publication timestamp are marked “Date unverified,” kept in a separate small section, and never compete above dated stories. Publication time and app fetch time are displayed separately.

The rank score uses inspectable signals: up to 5 points for publication recency across the freshness window, 1.6 for a selected topic, 1 for a selected region, 0.65 for India coverage, up to 1.5 for capped impact-word cues, up to 1.2 for distinct publisher coverage, and local feedback contributions. Each card’s **Why this is here** text shows the two largest non-zero score contributions; **Score breakdown** lists all non-zero contributions and their points. Impact-word cues are a weak text heuristic, not an editorial judgment. The list explains the rule score; it does not establish accuracy, importance, or certainty. Source checkboxes are an inclusion preference, not a popularity boost. Each source has a configurable `publisher_group`; multiple feed sections from the same publisher count once. Headlines with very high token overlap across sources are also collapsed when estimating independent coverage, so syndicated-looking repeats do not increase the corroboration score. Multiple sources alone never prove importance, and ordinary “breaking/live” wording does not add a score.

The geography pass cycles among close-scoring candidates and includes India when its story remains near the top score tier. A match to a preferred region can qualify a recent story; the variety pass still does not force region quotas. The final selection uses only recent, relevance-qualified candidates within the top score band; it intentionally shows fewer stories when other candidates are stale, undated, unrelated to selected topics/regions, or materially lower-ranked. It reports stale and undated counts rather than padding the briefing. When nothing qualifies, the page gives the selector’s reason and practical recovery steps, such as refreshing feeds, checking source status, or adjusting preferences. The settings page explains that topic/region choices boost matches, freshness removes older dated items, and briefing length is a maximum rather than a quota.

“More like this” and “Less like this” are local, reversible feedback. Each rating changes the chosen story by +1.2 or −1.2 points and contributes +0.65 or −0.65 to its topic and +0.45 or −0.45 to its region for matching stories; aggregate contributions are capped at three ratings per tag. “Undo preference” clears the rating for that story, removing its future contribution. Feedback remains in the local SQLite database and is never sent to feed publishers. Explanations show the net feedback contribution when it changes a story’s score.

Default exclusions are applied to RSS headline/excerpt text using whole-word matching. A narrow list of explicit civic and humanitarian terms can allow otherwise excluded entertainment-related coverage through (for example, a celebrity standing for election or leading a humanitarian response). Both the exclusion keywords and public-interest exception list are editable in `editorial.json`; excluded categories remain user-configurable in preferences. This is a simple local rule set, not human editorial review.

## Architecture

- `server.py`: local standard-library HTTP server, RSS/Atom parser, conservative event clustering, transparent relevance scoring, reading progress APIs, and SQLite/MySQL persistence adapter.
- `api/index.py`: Vercel request handler, private route gate, login/logout, schema initialization, and user-triggered refresh routing.
- `private_auth.py`, `database_config.py`: single-owner signed sessions, CSRF/origin checks, and MySQL target validation.
- `import_sqlite_to_mysql.py`: explicit, read-only-by-default, confirmed one-time import tool.
- `vercel.json`, `requirements.txt`, `.env.example`: function routing/duration, MySQL driver dependency, and environment variable names.
- `sources.json`: editable feed catalog and publisher terms notes.
- `editorial.json`: editable topic, region, and excluded-headline keyword rules.
- `index.html`, `styles.css`, `app.js`: responsive interface with filters, read/save/hide actions, preferences, loading/error/empty states, and feed status.
- `test_server.py`: standard-library `unittest` regression checks.
- `morning_signal.sqlite3`: created at first run; stores story metadata, permitted excerpts, publication and fetch timestamps, publisher-group/source associations and per-source last-seen timestamps, local relevance feedback, source checks, preferences, reading goal, read/save/hide state, personal notes, and explicitly completed deep-read history.

There is no automatic background scheduler. Refresh when you want a new briefing. The daily deep-read slot is selected only from dated, recent stories that match the weekday theme and pass the relevance rules; when none qualify, the feature says so. Important stories outside the theme can still rank in the main briefing. Clustering compares informative headline tokens, topic/region compatibility, and a 72-hour publication window; related feed links are kept with the cluster. It is a conservative heuristic, not editorial verification. Ranking and deduplication are also heuristics: keyword impact cues miss context, source metadata may be incomplete, and two genuinely independent outlets can publish very similar headlines. Feed parsing is bounded to 1 MB and 35 entries per source; DTD/entity declarations are rejected. Redirects stay on the same HTTPS publisher host. Unavailable, malformed, oversized, or unusable feeds fail independently with a sanitized timestamped error, and do not stop other sources from refreshing. Concurrent refreshes are rejected. It never fetches article pages.

Story context is generated locally from the stored RSS headline, short feed excerpt, and source metadata; there is no AI service or article-page request. The **Reading context** preference has three display modes: **Quick scan** shows a very short excerpt summary, source, and publication time; **Standard** (default) shows the feed-based summary and cautious category note; **More context** also shows the available RSS excerpt, recognized uncertainty notes, and links from other publisher groups attached to the cluster. All modes keep the original publisher link visible. Quick summaries use the first feed-excerpt sentence, shortened to 160 characters when needed; an absent or under-80-character excerpt gets an explicit insufficiency message in every mode. Standard summaries are capped at 260 excerpt characters. More context shows the stored excerpt (up to the collector's 420-character limit), which is still only a feed excerpt and never the full article. Morning Signal framing is labeled separately from quoted publisher wording. **Why it may matter** uses a cautious category template and does not establish impacts. **What’s not clear yet** appears in More context when the headline is marked developing/updated, clustered feed headlines contain a recognized opposing term pair, or the excerpt is absent or shorter than 80 characters. Conflict detection is a small word-pair heuristic; it can miss disagreement or mistake unrelated wording. All statements depend on what publishers include in their feeds. They cannot establish the full evidence, context, accuracy, or later developments in an article. **Sources** links the original publisher and, when available, one article link for each additional publisher group attached to that cluster. The app omits same-publisher feeds and headlines with very high token overlap from this list; that reduces duplicate-looking links but cannot confirm syndication or editorial independence. The old “Plain language” setting had no effect and maps to Standard; “Detailed” maps to More context during database initialization.

The reading goal starts at one article per day, intended to be the featured deep read, and is configurable in preferences. The “Today’s reading” panel features the theme-matched article; mark it complete after reading to record its local date and theme. Marking any story read contributes to the daily article count. The reading list is made from saved stories and articles with personal notes, and supports read/unread and remove/save actions. A note can be saved only on a read story and is limited to 280 characters. Weekly history contains only deep reads explicitly completed after this feature is installed; existing read flags are not treated as completion history. Reading-time labels appear only when a publisher feed supplies an explicit reading-time field. No full article pages are fetched to estimate duration.

## Known limitations

- RSS availability and publisher terms may change. TOI's permission is personal/non-commercial, so do not expose this local installation as a public or commercial feed aggregator.
- The source list remains deliberately small and concentrated: TOI, Guardian, CNA, and Le Monde are four publisher groups, with feeds weighted toward English-language national/international desks. India has one publisher (TOI); CNA and Le Monde broaden Asia, Europe, Africa, and the Americas but do not provide comprehensive local reporting. The disabled/unverified Africanews feed does not currently contribute. Regional tags and contributed-publisher counts cannot establish viewpoint diversity, and source selection is not proof of global balance.
- A feed directory is not a reporting desk: the app cannot guarantee 8–12 consequential stories, independent corroboration, factual accuracy, or full geographic balance when feeds do not provide them. Region and impact cues are inferred from headlines and excerpts. The score-bounded variety pass does not force quotas or fill weak slots; freshness/relevance filtering can leave a short briefing. A missing, naive, malformed, or implausibly future publication timestamp is unverified; a feed’s fetch time is never substituted for publication time. Stale articles are excluded from the briefing but may remain in saved/read history. Publisher groups and title similarity are imperfect ways to identify independent reporting and syndicated copies; they cannot verify the editorial independence of outlets or shared wire services.
- Category and region tags are simple local keyword heuristics. Region detection uses names and terms in feed titles/excerpts, so unnamed places and global stories may be labeled Global and explicit mentions can still mislead. The weekday slot only features a story when the available feed metadata matches that day's theme; it will show an empty feature state otherwise.
- Feed-based story summaries and “why it may matter” text do not have the full article context. Quick scan and Standard summarize only the excerpt text already collected; More context shows at most the stored RSS excerpt, not a full article. The app does not independently verify reports, infer consequences, or provide medical or financial advice. Developing labels depend on headline wording; conflict detection only catches a small configured set of opposing verbs. A short excerpt is a cue that context is limited, not proof that the publisher’s article lacks details. Open the original source links to review the reporting. The reading-context setting changes only the amount of feed metadata displayed; it does not simplify wording or change story ranking. Hidden stories are listed separately from read stories and can be restored from **Hidden stories**. Restoring clears only the hidden flag; the normal freshness, source, exclusion, and relevance selection runs again, so an old or currently irrelevant story may stay out of the briefing. The app has no permanent story deletion action.
- The weekday deep-read is a feed story selected by category, not a separately commissioned long-form article. Saturday/Sunday categories are necessarily approximate.
- Reading time is often absent because feeds do not provide it; the interface omits the estimate rather than deriving it from an article page. The goal counts stories marked read today, while weekly history counts only explicit completion of that day’s featured read. History is local to the laptop and begins empty; it is not backfilled from older read flags.

## Checks

Run the regression suite with `python -m unittest -v` (or `py -m unittest -v` on Windows). Fixture tests cover ranking, freshness timestamps and timezone conversion, stale/undated selection, explanations matching score components, preference changes and feedback undo, the no-qualifying-stories empty state, publisher-group deduplication, too-few qualifying stories, related/unrelated clustering, exclusions, weekday focus rules, geographic balancing and coverage, feed-context display modes and preference persistence, insufficient excerpts, reading progress, preference-gated source refreshes, successful and malformed feeds, migration of an older `story_sources` schema with data preservation, single-listener startup, safe URL handling, authentication, private route gates, CSRF, MySQL SQL translation, and fixture-only SQLite import behavior. They use mocked feeds and temporary databases; fixtures never enter the running briefing. You can also run `python -m py_compile server.py api/index.py private_auth.py database_config.py import_sqlite_to_mysql.py test_server.py test_deployment.py offline_evaluation.py` and `node --check app.js` for syntax checks.

Run the separate, deterministic editorial evaluation with `python offline_evaluation.py` (or `py offline_evaluation.py` on Windows). It uses invented, clearly labeled fixtures with a fixed UTC clock and makes no network requests or database writes. Its report lists the selected fixture headlines and the same short ranking reasons used by the interface, then reports pass/fail for regional variety and India inclusion, relevance, freshness, undated handling, exclusions and the civic exception, syndicated-copy counting, weekday deep-read theme, and the short-briefing behavior when fewer stories qualify. The unit suite runs the same evaluation assertions. These fixtures are only a regression/evaluation aid and must never be treated as current events or added to the real briefing.

The evaluation is intentionally small and rule-based. It checks expected behavior on chosen scenarios, not real-world editorial quality, recall, source credibility, or geographic fairness across all possible stories. Its synthetic attached-report cluster models a previously grouped event; the separate clustering unit tests cover title similarity, date proximity, region compatibility, and unrelated headlines. The evaluator does not prove that configured live feeds are reachable.

For a real-feed check, start the server and select **Refresh feeds** in the browser. Inspect **View source status** for each enabled feed’s last successful check or its latest failure. This check requires the laptop to reach the publisher RSS endpoints; feeds can be temporarily unavailable, and no proxy or scraping fallback is used. On 2026-10-22, a local check of the five selected TOI and Guardian feeds completed with 5 successes, 0 failures, and 33 new stories; this is a point-in-time result and does not guarantee future availability.

The project has no automated browser or screen-reader test runner. For accessibility and responsive checks, use a browser at desktop width and around 768 px, 480 px, and 320 px. Tab through the page and confirm the focus outline stays visible; open and close **Briefing preferences** with the keyboard; check that filter buttons expose their pressed state, the hidden-stories toggle exposes expanded state, story actions name their story, and status updates are announced. Confirm long headlines and publisher names wrap without horizontal scrolling, settings remain scrollable on a short screen, and the loading, empty, and error messages remain visible. The page uses native buttons, labeled form controls, a named settings dialog, live status regions, and reduced-motion styles, but these manual checks do not replace testing with a screen reader and keyboard across supported browsers.

## Security and privacy

- Local mode binds to loopback and uses SQLite. Vercel mode routes pages and APIs through the authenticated Python handler; JSON endpoints keep their bounded body, field, and value checks. Static files are served from an allowlist after authentication. Never expose the unauthenticated local server through a proxy, tunnel, or LAN bind.
- Vercel mode requires the five environment variables above and verifies the configured origin against the request host. The session is an HMAC-signed, 12-hour `__Host-` cookie with `Secure`, `HttpOnly`, and `SameSite=Strict`; state changes require its CSRF token. Secrets are not in the repository or browser code. The app does not use external accounts, telemetry, cloud reading analytics, or a client-side database.
- The authenticated MySQL database holds the same personal categories of data as local SQLite: story metadata and feed excerpts, preferences, saved/read/hidden flags, notes, feedback, source status, and explicit reading history. Treat MySQL provider credentials and backups as sensitive and apply the provider's access controls. No user data is copied until the operator explicitly runs the confirmed importer.
- Responses include a restrictive Content Security Policy and protections against MIME sniffing, framing, referrer leakage, and caching. Feed-provided titles, excerpts, names, and links are untrusted. Publisher links must be valid public HTTPS URLs; non-HTTP schemes, credentials, local hosts, and nonstandard ports are rejected.
- Feed URLs must use HTTPS. Redirects are restricted to the same publisher host (allowing the `www` alias). Feed reads have a timeout and size cap. Source errors are generalized so URLs and local exception details are not copied into the UI/database. The Vercel request handler returns a generic database error instead of exception details and does not log request bodies or headers.
- Feed URL checks block literal private IPs and common local hostnames. They do not pin DNS answers, so a public DNS name could resolve to a private address; only use feed URLs from publishers you trust. The source list is editable configuration, not authenticated. Avoid credentials or secret query tokens in feed URLs.
